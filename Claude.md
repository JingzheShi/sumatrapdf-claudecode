## Project Overview

SumatraPDF is a multi-format document reader (PDF, EPUB, MOBI, CBZ, CBR, FB2, CHM, XPS, DjVu) for Windows, written in C++ using Win32 API. Licensed under (A)GPLv3.

We don't use STL but our own string / helper / container functions implemented in `src/utils/`.

Assume that Visual Studio command-line tools are available in the PATH environment variable (cl.exe, msbuild.exe etc.)

## Build Commands

- **Build (debug):** `bun ./cmd/build.ts` — produces `./out/dbg64/SumatraPDF.exe`
- **Build tests:** `bun ./cmd/run-tests.ts` — builds and runs `test_util.exe` (release, x64)
- **Format code:** `bun ./cmd/format.ts` — runs clang-format on all src/ and relevant ext/ files
- **Regenerate VS projects:** `bun ./cmd/premake.ts` — runs premake5 for vs2022 and vs2026
- **Debug:** `windbgx -Q -o -g ./out/dbg64/SumatraPDF.exe`

After making a change to .cpp, .c or .h file (and before running build.ts), run clang-format on those files to reformat them in place.

Don't automatically commit changes. Always wait for explicit command to commit changes.

## Code Generation

Several source files are generated from TypeScript definitions in `cmd/`. Always edit the `.ts` source and regenerate — never edit the generated `.h`/`.cpp` files directly.

### Adding a new advanced setting
- Edit `cmd/gen-settings.ts`
- Run `bun cmd/gen-settings.ts` to regenerate `src/Settings.h` and `src/Settings.cpp`

### Adding a new command
- Edit `cmd/gen-commands.ts`
- Run `bun cmd/gen-commands.ts` to regenerate `src/Commands.h` and `src/Commands.cpp`
- Document in `docs/md/Commands.md`
- Document in `docs/md/Version-history.md` in **next** section

### Adding a new cmd-line flag
- Edit `cmd/gen-flags.ts`
- Run `bun cmd/gen-flags.ts` to regenerate `src/Flags.h` and `src/Flags.cpp`
- Implement handling in `Flags.cpp`
- Document in `docs/md/Version-history.md` in **next** section

## Architecture

### Directory layout
- `src/` — application source code
- `src/utils/` — custom utility library (strings, files, containers, Win32 helpers) used instead of STL
- `src/wingui/` — Win32 GUI widget wrappers (buttons, edits, layout, tree views, webview, etc.)
- `src/mui/` — custom minimal UI framework (text rendering)
- `src/uia/` — UI Automation accessibility support
- `ext/` — third-party libraries (zlib, freetype, harfbuzz, libjpeg-turbo, openjpeg, libdjvu, bzip2, etc.)
- `mupdf/` — MuPDF rendering library (the core PDF/EPUB/XPS renderer)
- `cmd/` — TypeScript build scripts and code generators (run with `bun`)
- `vs2022/`, `vs2026/` — Visual Studio solution/project files (generated by premake5)
- `premake5.lua` — premake5 project definition

### Document engine architecture
Each document format is handled by an engine class. All engines implement a common interface defined in `src/EngineBase.h`. Engine types are identified by `Kind` constants (e.g., `kindEngineMupdf`, `kindEngineDjVu`, `kindEngineEpub`).

Key engine files:
- `EngineMupdf.cpp` — PDF, XPS, EPUB, FB2 (via MuPDF)
- `EngineDjVu.cpp` — DjVu format
- `EngineImages.cpp` — images, comic books (CBZ/CBR)
- `EngineEbook.cpp` — MOBI, PDB, CHM, HTML, TXT
- `EnginePs.cpp` — PostScript (via Ghostscript)
- `EngineCreate.cpp` — factory that selects the right engine for a file

### Application structure
- `SumatraStartup.cpp` — application entry point and initialization
- `SumatraPDF.cpp` — main application logic and window management
- `MainWindow.h` — main window state (`MainWindow` struct)
- `WindowTab.h` — per-tab state (`WindowTab` struct)
- `Tabs.cpp` — tab management
- `Canvas.cpp` — document rendering canvas and input handling
- `DisplayModel.cpp` — page layout, scrolling, zoom logic
- `RenderCache.cpp` — asynchronous page rendering cache
- `Menu.cpp` — application menus
- `Toolbar.cpp` — toolbar
- `TableOfContents.cpp` — TOC sidebar
- `SearchAndDDE.cpp` — text search and DDE inter-process communication
- `GlobalPrefs.h` — global preferences struct
- `Settings.h` — advanced settings (generated)
- `Translations.cpp` — i18n support

### Installer
`Installer.cpp` and `Uninstaller.cpp` — SumatraPDF bundles its own installer (no external installer framework).

## Windows Shell Safety

The Bash tool runs under Git Bash (MSYS2), **not** cmd.exe. This causes critical issues with Windows-style commands:

- **NEVER use `2>nul`** — Bash interprets this literally and creates a file called `nul`. On Windows NTFS, `nul` is a reserved device name, making the file extremely difficult to delete (requires UAC/admin privileges). Use `2>/dev/null` instead.
- **NEVER use `rmdir /s /q`** — Bash `rmdir` does not understand cmd.exe flags. Use `rm -rf` instead.
- **NEVER use `del`** — Not available in Bash. Use `rm` instead.
- **NEVER use `dir`** — Use `ls` instead.
- **For Windows-native commands**, wrap in `cmd /c "..."` explicitly.
- In general, always use Unix-style commands and paths in the Bash tool.
